## User stories
- Format: "As a <role from the glossary>, I want <capability>, so that <benefit>." The benefit is the reason, not the capability again.
- Check INVEST: Independent, Negotiable, Valuable, Estimable, Small, Testable. Split any story that fails "Small" or "Testable".
- Write acceptance criteria as a checklist or as Given/When/Then. Each one is testable by one person without asking.
- Use glossary Terms for roles and objects. Out-of-scope items go in their own list.
