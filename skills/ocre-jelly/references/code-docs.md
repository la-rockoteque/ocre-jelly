# Code docs: comments and doc comments

`docs` mode audits or rewrites the prose inside comments and doc comments. The code, the doc syntax and the doc generator's output format never change.

## What never changes

- Code, including the code inside examples, doctests (`>>>`), `<code>`, `{@code}` and fenced blocks.
- Tag names and tag order: `@param`, `@returns`, `<summary>`, `:param x:`, `- Parameter x:`, `# Errors`.
- Parameter names, types (`{string}`, `[Integer]`, `:type:`), `cref`/`{@link}`/`[Foo]` targets, `<inheritdoc/>`, `{@inheritDoc}`.
- Tool markers: `ponytail:`, `TODO:`, `FIXME:`, lint directives. The generated placeholders listed below are the one exception.
- Identifiers. If a name breaks the ubiquitous language, report it; renaming is a code change, so it is out of scope here.

After a rewrite, run `codedoc.py --same-code original rewritten`. Any answer except `code unchanged` blocks.

## Rules for every format

1. **The summary adds what the signature doesn't say**: behavior, units, side effects, errors, what happens with null or empty input, thread safety. "Gets the user name." on `GetUserName` is an `echo-doc` finding.
2. **Echo doc with nothing to add**: delete it, unless the project requires docs on that symbol. Signs that it does: CS1591 or `GenerateDocumentationFile`, eslint `jsdoc/require-jsdoc`, `-Xdoclint`, Rust `missing_docs`, pydocstyle D1xx. When docs are required, write a real summary, or use `<inheritdoc/>`/`{@inheritDoc}` on overrides.
3. **Parameters**: state constraints, units, allowed values and null handling, not the name again (`param-echo`).
4. **Returns**: say what is returned, and in which case (empty, null, -1). "The result." is a `returns-echo` finding.
5. **Line comments explain why, not what.** Delete a comment that narrates the next line (`// increment i`). Keep one that records a reason, a constraint or a link.
6. **STE100 applies to the prose**: one topic per sentence, 25 words or fewer, simple verbs. The summary mood follows the format's convention (table below), not STE's imperative, because a summary describes; it doesn't instruct.
7. **Use glossary Terms** in doc prose.

## Summary conventions by format

| Format | Summary sentence | Prose-bearing syntax (other syntax is fixed) |
|---|---|---|
| JSDoc | Third person: "Returns the TTL in seconds." | Text after `@param {T} name -`, `@returns {T}`, `@throws {T}` |
| TSDoc / TypeDoc | Third person. No `{Type}`: TypeScript has the types | `@param name -` (hyphen required), `@returns`, `@remarks` |
| Javadoc | Third person. It ends at the first period followed by a space, so avoid "e.g. " in it | `@param name` (no hyphen), `@return` (singular), `@throws X` |
| KDoc | Third person; first paragraph | `@param`, `@return`, `@throws`, `@property`; `[name]` links |
| .NET XML docs | Properties "Gets or sets …"/"Gets …"; booleans "Gets a value indicating whether …"; constructors "Initializes a new instance of the <see cref="T"/> class." | `<summary>`, `<param>`, `<returns>`, `<exception>`, `<remarks>` |
| Python (PEP 257) | Imperative: "Return the user." One line, ending with a period, then a blank line | Google `Args:`/`Returns:`, NumPy sections, reST `:param x:` |
| Go | A full sentence that starts with the name: "Parse reads …" | `Deprecated:` paragraph; `[Name]` links |
| rustdoc | Third person, one line | `# Examples`, `# Errors`, `# Panics`, `# Safety`; [`Name`] links |
| Doxygen | `@brief` or autobrief first sentence | `@param[in] name`, `@return`, `@retval` |
| PHPDoc | Third person | `@param Type $name`, `@return Type`, `@throws` |
| Swift markup | Third person | `- Parameter name:`, `- Parameters:`, `- Returns:`, `- Throws:` |
| YARD (Ruby) | Third person | `@param name [Type]`, `@return [Type]` |

## Generated placeholders (`generated-doc`)

Doc generators leave stubs that are always findings:
- GhostDoc: `<autogeneratedoc />` and `// TODO Edit XML Comment Template for X`.
- autoDocstring: `_summary_`, `_description_`, `_type_`, `_extended_summary_`.
- Document This and IDE stubs: `@param {*} name`, and tag lines with no text (`@param id`, `@return`).

Fix a placeholder by writing the real text (rules 1 to 4), or by deleting the comment when rule 2 allows it. Remove the generator's marker in the same edit. The doc-convention modules (`modules.py list`) add opinions for each format and generator.
