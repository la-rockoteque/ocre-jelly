# Prose authority: ASD-STE100 Simplified Technical English

ocre-jelly follows ASD-STE100 (Simplified Technical English). This file restates its writing rules in our own words. It does not copy the official dictionary, which is copyrighted and available from asd-ste100.org. When a rule here conflicts with a preset or taste, this file wins. The preservation rules in SKILL.md win over this file: never change a fact to satisfy STE.

## Words

- Use common, concrete words, and use each word with one meaning only. "Replace" means install a new part. Don't also use it to mean "put back".
- Use one term for one thing throughout. Don't alternate between "valve", "unit" and "component" for the same part.
- Technical names (parts, tools, software, units) and technical verbs (for example "calibrate", "deploy" or "compile") are allowed as the domain needs them. Never simplify these.
- Use the simplest word that works: "use" not "utilize", "start" not "commence", "help" not "facilitate", "show" not "demonstrate".
- Don't stack more than three nouns in a row. "Engine fuel pump inlet valve" becomes "the inlet valve of the engine fuel pump".

## Verbs

- Use simple verb forms: the simple present, the simple past, the future ("will"), the imperative and the infinitive. Use a past participle only as an adjective ("the removed cover").
- Avoid "-ing" verb forms except in technical names ("heating element") and where no other form is clear.
- Prefer the active voice. In instructions, always use it. In descriptions, use the passive only when the actor is unknown or unimportant.
- Use the verb, not a noun made from it: "inspect the seal", not "carry out an inspection of the seal".
- Avoid phrasal verbs when a single verb exists: "remove", not "take out"; "find", not "figure out".

## Sentences

- Keep instructions to 20 words or fewer. Keep descriptive sentences to 25 words or fewer.
- Write about one topic per sentence.
- Don't drop articles or verbs to make text shorter. "Close the valve" is correct. "Close valve" is not.
- Use a vertical list when a sentence has several parallel items or steps.

## Instructions (procedures)

- Use the imperative: "Tighten the bolt."
- Write one instruction per sentence. You can combine two actions only if the user must do them at the same time.
- Put a condition before the action: "If the light is red, stop the pump."
- Start a warning or caution with a clear command, then give the risk: "Disconnect the power. High voltage can kill you."

## Descriptions

- Put the most important information first.
- Write one topic per paragraph, and no more than six sentences per paragraph.
- Use connecting words ("then", "because", "but") to show how sentences relate. Don't leave the reader to guess.

## Applying STE to a rewrite

- STE findings are **soft**: confirm them in context the same way as the patterns in `patterns.md`.
- Apply STE fully to technical text: docs, procedures, READMEs, runbooks, specs and release notes. For other registers (emails, blog posts, marketing), apply only the vocabulary and clarity rules. Don't turn a warm email into a maintenance manual.
- Quotes, code, UI strings and attributed text are never rewritten into STE.
- A sentence that is over the length limit but otherwise clear can stay in audit mode. Report it; split it only in rewrite mode.
