# Troubleshoot

## The session doesn't show "Loading ocre-jelly prose mode..."

1. Check that the plugin is installed and enabled: `claude plugin details ocre-jelly@ocre-jelly`.
2. Restart Claude Code. Hooks load at startup.
3. Check that `OCRE_JELLY` isn't set to `off`, and that no config layer sets `"enabled": false`: `modules.py config show`.
4. Run the hook by hand from the repo: `echo '{}' | python3 $OJ/modules.py hook session-start`. It prints the rules, or an error on stderr.

## A config setting has no effect

- Run `modules.py config show`. The last line says which layer set each key.
- Run `modules.py config path` to see which files exist.
- A layer with an invalid value is ignored as a whole, with a message on stderr: `ocre-jelly: …/ocre-jelly.json: 'locales' has the wrong type`. Fix the value; the other layers still apply.
- `config set` refuses invalid values before it saves them.

## Too many findings

- Long sentences in code comments: raise `thresholds.sentence_words`, or lower `length_hits_per_file`.
- Glossary aliases everywhere: an alias applies only in its own bounded context. Check the glossary's `##` sections and the **Flagged ambiguities**, or add the word to a `UI label` column.
- One category is noise for your repo: `config set severity '{"<category>":"off"}' --project`.
- Generated files: add them to `ignore_paths`.

See [Tune the checks](tune-checks.md).

## A finding looks wrong

Every soft finding is a candidate. Claude confirms it in context, and protects literal, quoted, attributed and domain-valid uses. If a pattern is wrong for everyone, fix it in `locales/<tag>.py`, and add a self-test line in `scan.py` that proves it.

## `--same-code` says the code changed, but I only edited comments

The gate is strict on purpose. A trailing comment passes when the code before it is the same. It fails when:

- a block comment's inner lines don't start with `*`, or
- the edit also changed spacing inside code.

Keep comment edits inside comment lines.

## Export says "skip … exists and was not generated by ocre-jelly"

The target file exists and has no ocre-jelly marker, so the export won't overwrite it. Move the file, merge it by hand, or pass `--force` if you are sure.

## Self-tests

```bash
./setup.sh --check
```

This runs the self-test of each script and checks that the generated reference pages are up to date.
