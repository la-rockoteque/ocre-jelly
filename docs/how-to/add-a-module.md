# Add a module

A module is one markdown file in `skills/ocre-jelly/modules/`. It needs no code, unless it exports a file that has to be computed.

## A rules module

Create `skills/ocre-jelly/modules/sphinx.md`:

```markdown
---
kind: rules
when: editing Sphinx .rst docs or conf.py
default: auto
detect_files: docs/conf.py, conf.py
description: Sphinx and reStructuredText conventions
---
## Sphinx
- Use one heading underline style per level, the one the project already uses.
- Cross-reference with roles (:func:, :class:), never with bare URLs to the same docs.
- Keep code in `.. code-block::` directives with a language.
```

Frontmatter keys:

| Key | Values | Meaning |
|---|---|---|
| `kind` | `rules` or `export` | Rules text for the session, or a file to write. |
| `when` | one line | The trigger. It becomes the index line: "Before work that matches one, read …". Required for rules modules. |
| `default` | `on`, `off`, `auto` | The state when no config layer sets one. Use `off` for opinions a team must opt into. |
| `detect` | plugin names | For `auto`: on when one of these plugins is installed. |
| `detect_files` | shallow globs | For `auto`: on when one matches at the repo root or one folder down (`*/tsconfig.json`). `**` is rejected, to keep session start fast. |
| `inject` | `always` | Inline the whole body every session instead of an index line. Use it rarely. |
| `description` | one line | Shown by `modules.py list` and in the reference. |

Body rules: short imperative bullets, one rule per line, with concrete examples. The body follows the [writing standards](../explanation/standards.md). Scan it before you commit: `scan.py --no-config < skills/ocre-jelly/modules/<name>.md`.

## An export module

```markdown
---
kind: export
default: off
target: .zed/ocre-jelly.md
description: Zed assistant rules
---
<!-- Generated by ocre-jelly. Edit ocre-jelly, then re-export. -->

{{rules}}
```

- `target` is a path from the repo root, and it must stay inside the repo.
- `{{rules}}` expands to the core rules, the locale line and every active rules module, inlined.
- Keep the `Generated by ocre-jelly` marker. Without it, a later export refuses to overwrite the file.
- `write: block` upserts a marked block into an existing file instead of owning the whole file (see `agents-md.md`).
- `needs: glossary` skips the export when the repo has no glossary.

When the output must be computed, add `skills/ocre-jelly/modules/<name>.py` with a `render(ctx) -> str` function. `ctx` holds `rules` (text), `rows` (glossary rows as `(terms, aliases, labels)`), `aliases` (alias to Terms) and `mark` (the marker text). See `vale.py` and `cspell.py`.

## Check it

```bash
./setup.sh --check                               # every module parses; rules modules have a when:
python3 skills/ocre-jelly/scripts/gen_docs.py    # refresh docs/reference/modules.md
```

`setup.sh --check` fails until the reference page is regenerated.
