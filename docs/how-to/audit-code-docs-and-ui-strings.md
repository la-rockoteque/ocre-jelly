# Audit code docs and UI strings

`docs` mode checks the prose inside source files: line comments, doc comments and the user-facing values of string resources. It never changes code.

## Audit

```
/ocre-jelly docs audit src/api/users.ts src/api/orders.ts
```

For a folder, Claude lists the source files first, and asks you to confirm when there are more than 20.

You can run the scanner yourself:

```bash
python3 $OJ/codedoc.py src/api/*.ts
python3 $OJ/codedoc.py --json src/**/*.cs > findings.json
```

## Only what changed

On an existing repo, check only the lines you added:

```bash
git diff | python3 $OJ/codedoc.py --diff             # uncommitted changes
git diff main... | python3 $OJ/codedoc.py --diff     # a branch, for a PR
```

It scans each changed file whole, so the checks keep their context, then reports only findings on added lines. A doc-comment finding such as `echo-doc` counts when the diff touches any line of the block. Legacy prose you didn't touch stays quiet, so the repo needs no baseline. Markdown and text files in the diff get the prose checks too.

## What it reads

| Source | What is scanned | What is masked |
|---|---|---|
| JS/TS, Java, Kotlin, C#, Go, Rust, Swift, PHP, C/C++, Scala, Dart | `/** */`, `/* */`, `///`, `//!`, `//` comments | Tags, `{types}`, parameter names, `{@link}`, XML elements, `@example` blocks, fenced code |
| Python | Docstrings and `#` comments (exact, with `tokenize`) | reST and Google fields, NumPy sections, doctests (`>>>`) |
| Ruby, shell, YAML, Perl, R, Terraform | `#` comments | YARD `[Type]` |
| i18n JSON, `.arb`, `.po`, `.resx`, `.properties`, `.strings`, `.xlf` | Each user-facing value, one by one | Keys, `{{placeholders}}`, `{name}`, `%s`, `$t(...)`, tags |

## Findings that only code docs have

| Category | Example | Fix |
|---|---|---|
| `echo-doc` | "Gets the user name." on `GetUserName()` | Say what the name doesn't: units, null handling, errors. Or delete it when docs aren't required. |
| `param-echo` | `@param id The id.` | State the constraint: "Positive database id. Throws when unknown." |
| `returns-echo` | `@returns The result.` | Say what is returned, in which case. |
| `generated-doc` | `<autogeneratedoc />`, `_summary_`, `@param {*} x` | Write the real text, then remove the marker. |
| `this-method` | "This method is used to…" | Start with the verb: "Retries the call…". |

Each format has its own summary convention: third person in Javadoc ("Returns…"), imperative in Python ("Return…"), the name first in Go ("Parse reads…"). The doc-convention modules turn on from project files and hold these rules. See [Modules](../reference/modules.md).

## Rewrite, and prove the code didn't change

```
/ocre-jelly docs src/api/users.ts
```

Claude keeps a copy of each original file, edits only the comment text, then runs:

```bash
python3 $OJ/codedoc.py --same-code original/users.ts src/api/users.ts
```

The gate uses two independent checks: it strips the comments and compares the code, and it diffs the lines to confirm that each changed line is a comment. Any answer except `code unchanged` undoes the edit.

## UI strings

The scanner reads the locale from the path, so `fr-CA/common.json` gets the fr-CA checks. Glossary UI labels are valid words. Repeated alias hits in one file collapse into a single line with a count, and `--all` lists each one.

## Opinionated modules for generated docs

Turn these on when the repo uses the tool:

```bash
python3 $OJ/modules.py enable ghostdoc --project        # GhostDoc .NET XML docs
python3 $OJ/modules.py enable doc-generators --project  # autoDocstring, Document This, IDE and AI doc stubs
```
